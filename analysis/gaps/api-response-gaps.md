# Merge fields with no matching API response field

Collated from every template in [`../mappingResults`](../mappingResults) — every merge field whose `API Response available` was **No** or **Partial** against `PcrHearingResult` (`GET /cases/{caseURN}/hearings/{hearingId}/defendants/{defendantId}`, `api-cp-crime-results-pcr/src/main/resources/openapi/openapi-spec.yml`, served by `service-cp-crime-results-pcr`).

Two structural gaps drive most of the **Partial** entries: the PCR schema has no stable `promptReference` key (prompts arrive as display `{label, value}` pairs only, so a template's `dp.value('promptReference')` call has nothing to match against), and no judicial-result-type UUIDs (`resultIdentifierExists(...)` checks and per-UUID prompt lookups can't resolve at all).

- **No** (field/concept absent from the API response entirely): 81 distinct fields
- **Partial** (concept reachable only via fuzzy label-matching, not a stable key): 125 distinct fields
- **Total gap fields:** 206 distinct field names, 678 template occurrences
